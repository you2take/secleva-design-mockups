# Secleva 店舗ページ 管理画面（owner）実装ガイド

本ディレクトリは **本番の `https://secleva.com/owner` 配下にマージする前提のモック** です。  
本番取り込み時に必要な実装情報をまとめます。

---

## 🌐 本番反映先

```
https://secleva.com/owner                       ← 既存：オーナー管理画面トップ
                                                   （LINE Login OAuth 認証必須）
https://secleva.com/owner/settings              ← 既存：設定 hub
https://secleva.com/owner/settings/shop-lp      ← 新規：店舗ページ（本モック群がここに入る）
  ├── ?step=template                            ← 01_template-select.html 相当
  ├── ?step=edit                                ← 02_block-edit.html 相当（デフォルトstep）
  └── ?step=preview                             ← 03_preview.html 相当
```

サブルートはクエリで分岐 or `/shop-lp/template` `/shop-lp/edit` `/shop-lp/preview` のパス分岐どちらでも可（実装側で選択）。

### 認証
- `/owner` 階層は **LINE Login（LINE OAuth v2.1）** で保護
- 未認証時は `https://access.line.me/oauth2/v2.1/login?...` にリダイレクト
- 本モックは認証後の状態（ログイン済み）を前提

### 前提条件（オンボーディング完了状態）
本モックUIが動く前提として、以下が **`https://secleva.com/apply` のサポート対応**で完了済み：

1. オーナーが Secleva サポート LINE に友だち追加（`/apply`の Step 1）
2. 店舗情報 3 項目を LINE で返送（業種・店舗名・住所など）
3. **Secleva サポート運営側が LINE 公式アカウントを開設・設定**（オーナー作業不要）
4. 準備完了メール → オーナーは管理画面（`/owner`）にログイン
5. ここで本モックの UI（`/owner/settings/shop-lp`）が触れる状態

→ **LINE 公式アカウントの開設は Secleva サポートが代行する**前提なので、Block 7「SNSリンク」の `LINE公式` URL は **デフォルトで運営が事前入力**しておく運用想定。オーナーはあとから自分のSNSを追加するだけ。

### 公開ページとの関係
| URL | 用途 | 認証 |
|---|---|---|
| `secleva.com/SHOP-{id}` | 店舗ページ（一般公開・MEO 対象） | なし |
| `secleva.com/apply` | 申込フロー（サポート対応） | なし |
| `secleva.com/owner` | オーナー管理画面トップ | LINE Login |
| `secleva.com/owner/settings/shop-lp` | 本モック（店舗ページ編集） | LINE Login |
| `secleva.com/owner/settings/menus` | メニュー管理（料金・追加削除） | LINE Login |

## 🔁 メニュー写真の3 state パターン

`02_block-edit.html` の **Block 5: メニュー写真** で、登録メニュー1件あたり3つの状態を出し分ける。

### state="custom"（マイ写真）
- バックエンドの `menu.photo_url` が存在する場合
- サムネ：オーナー写真をそのまま `<img src="{{ menu.photo_url }}">` 表示
- ラベル：`マイ写真`
- ボタン：`✏ 編集`

### state="default"（デフォルト表示中）
- `menu.photo_url` がない & 業界デフォルトカテゴリにマッチする場合
- サムネ：`branding/dummy/default/menu/{matched}.webp` 表示＋ `DEFAULT` バッジ
- ラベル：`デフォルト表示中`
- ボタン：`✏ 編集`

### state="empty"（写真未設定）
- `menu.photo_url` がない & デフォルトもマッチしない場合（業種が特殊・カテゴリ未設定など）
- サムネ：破線枠＋カメラアイコン
- ラベル：`写真未設定`
- ボタン：`+ 写真を追加`

→ 各stateの完全マークアップは `02_block-edit.html` の Block 5 直下の HTML コメントを参照。

### マッチングロジック（推奨）
バックエンドで `menu.name` または `menu.category` をキーにデフォルト画像を選択：
```
"もみほぐし" "整体" "リンパ" → default/menu/01_oil.webp
"アロマ" "ハーブ" "オイル"   → default/menu/02_aroma.webp
"フェイシャル" "クレンジング" → default/menu/03_towels.webp
"ホットストーン" "リフレ"    → default/menu/04_stones.webp
それ以外                     → state="empty"
```

## 🔗 プレビュー画面（03）からの共有・コピー動線

`03_preview.html` 上部ヘッダー右の **「リンクを送る」** と、ステータス行右の **「リンクをコピー」** は別々の挙動。

> 文言は意図的に「URL」ではなく「リンク」を使用。低リテラシーオーナー（50代女性想定）に伝わりやすい言い換え。  
> 下書き状態でも使えることをヘルパーバナーで明示：「公開前でも、リンクを友だち・スタッフに送って下見してもらえます。」

### リンクを送る（右上アイコン）
- **用途**：友人・スタッフ・取引先などに公開URLを送る
- **想定挙動**：
  1. **モバイル**：`navigator.share()` でOS標準シェアシートを起動  
     → LINE / Mail / Messages / Twitter / Instagram DM 等をユーザーが選択
  2. **PC**：シェアシート未対応の場合は「URLをコピー」と同等のフォールバック ＋ トースト「コピーしました」

```js
// 実装サンプル
async function shareShopUrl() {
  const url = `https://secleva.com/SHOP-${shopId}`;
  const title = `${shopName} | Secleva`;
  if (navigator.share) {
    try { await navigator.share({title, url}); } catch(e) {}
  } else {
    await navigator.clipboard.writeText(url);
    showToast('URLをコピーしました');
  }
}
```

### リンクをコピー（ステータス行）
- **用途**：自分のメモ / ブラウザ別タブ / 既存LINE個別投稿に貼る等
- **想定挙動**：`navigator.clipboard.writeText()` で公開URLをクリップボードに格納 ＋ 視覚フィードバック（アイコン変化 or トースト「コピーしました」）

```js
async function copyShopUrl() {
  const url = `https://secleva.com/SHOP-${shopId}`;
  await navigator.clipboard.writeText(url);
  showToast('URLをコピーしました');
}
```

### 公開状態（下書き / 公開中）との関係
| 公開状態 | URL生成 | 「共有」「コピー」挙動 |
|---|---|---|
| 下書き | `https://secleva.com/SHOP-{id}` は存在するが**非公開**（一般アクセス時404） | コピー/共有自体は可能。受け手側で「ページが見つかりません」表示 → 公開後に再共有を促すUX推奨 |
| 公開中 | `https://secleva.com/SHOP-{id}` 一般公開 | フル機能 |

下書き状態で共有する場合は、シェア時にトーストで **「下書き状態のURLを共有します。公開してから送り直すこともできます」** と案内するとフリクション減。

### 実装時のコピー文言
- 共有時の `share.title`（例）：`{shopName} | Secleva`
- 共有時の `share.text`（例）：`{shopName} の店舗ページです。`
- トースト：`コピーしました` / `URLをコピーしました`

## 🔖 メタタグ・OGP・ファビコン（自動設定）

公開ページ（`secleva.com/SHOP-{id}`）には、以下の SEO/SNS メタ情報が **自動的に注入**される。オーナーは特別な操作なし。

### 4項目の自動マッピング

| メタ要素 | ソース | 用途 |
|---|---|---|
| **タイトル**（`<title>` / `og:title` / `twitter:title`） | `shop.name`（店舗名） | ブラウザタブ／検索結果／SNS シェア時の見出し |
| **ディスクリプション**（`description` / `og:description` / `twitter:description`） | `shop.lead_copy`（リードコピー） | 検索結果のスニペット／SNS シェア時の説明文 |
| **メタ画像**（`og:image` / `twitter:image`） | `shop.hero_image_processed`（ヒーロー画像を1200×630にクロップ＋ロゴウォーターマーク） | LINE/Twitter/Facebook 等での共有時のサムネ。**未設定時は OG タグ自体を省略** |
| **ファビコン**（`<link rel="icon">` / `apple-touch-icon`） | **`shop.logo`（オーナーが Block 2 でアップロードした店舗ロゴ）**を 32×32 / 180×180 にリサイズ | ブラウザタブ・iOS ホーム画面アイコン |

> ⚠️ ファビコンに **Secleva ブランドロゴを使わない**。オーナー各店舗が設定した独自ロゴを必ず使う（モックでは `branding/dummy/shop-logos/T{1-5}.webp` で5店舗分のサンプルを配置）。

### 🎯 「店舗ロゴ」の表示一貫性ルール

`shop.logo`（オーナーが Block 2 でアップロードする画像）は、**以下3箇所で必ず同一画像を使う**。

| 表示位置 | 仕様 | 備考 |
|---|---|---|
| ① ヒーロー直下の円形ロゴ（Block 2） | 円形クロップ＋`object-cover`。テンプレ装飾（縁取り・影）はテンプレ側で調整 | テンプレに依存しない `<img>` 出力。**テキスト（「結」「M」「RGE」等）でCSS描画しない** |
| ② ブラウザタブのファビコン | サーバーで 32×32 / 180×180 にリサイズ | `<link rel="icon">` / `<link rel="apple-touch-icon">` |
| ③ OGP画像のロゴウォーターマーク（任意） | サーバーで 1200×630 ヒーローの左下に合成 | 未設定時はスキップ |

> 💡 オーナーは「店舗ロゴ」を **1枚アップロードするだけで** ブラウザタブ・ページ内・SNSシェア時 すべてに反映される。**テンプレを切り替えても同じロゴが追従する**設計。
>
> モックでは各テンプレ専用のサンプルロゴを `branding/dummy/shop-logos/T{N}_*.webp` に配置し、ヒーロー円形ロゴとファビコンに同じ画像を参照させている。

### サーバー側で生成するHTML例
```html

<meta name="description" content="{{ shop.lead_copy }}">
<link rel="icon" type="image/png" href="{{ shop.logo_favicon_32 }}">

<!-- OGP -->
<meta property="og:type" content="website">
<meta property="og:title" content="{{ shop.name }}">
<meta property="og:description" content="{{ shop.lead_copy }}">

<!-- Twitter Card -->

<meta name="twitter:title" content="{{ shop.name }}">
<meta name="twitter:description" content="{{ shop.lead_copy }}">
{% if shop.hero_image_processed %}
<meta name="twitter:image" content="{{ shop.hero_image_processed }}">
{% endif %}
```

### ヒーロー画像の加工パイプライン（og:image用）

オーナーがアップロードした写真を OGP 用にサーバー側で加工：

1. **入力**：`shop.hero_image`（オリジナルサイズ）or デフォルト `00_hero.webp`
2. **クロップ**：1200×630（OGP 推奨アスペクト 1.91:1）
3. **オーバーレイ**（任意）：左下にロゴ + 店舗名のタイポグラフィ
4. **出力**：`/SHOP-{id}/og.webp` に保存、CDN 配信
5. **キャッシュ**：店舗情報更新時に regenerate（`updated_at` をクエリパラメータで cache bust）

| `shop.lead_copy` が未設定 | description は店舗名＋業種で自動生成（例：「{name} | {category} のお店ページ」） |

## 🖥️ PC viewport 対応（モバイルUI + 装飾サイドバー）

公開ページ（T1〜T5）は **モバイルファースト**だが、PC（≥1024px）で開いた時も**スマホUIをそのまま中央配置 + 左にテーマ装飾サイドバー**を表示する。  
既存LP（`secleva.com/`）と同じパターンを踏襲。

### 共通の設計
- `@media (min-width: 1024px)` で発火
- ボディ全面に **テンプレ色のグラデーション背景**
- モバイルコンテナ（max-w 390〜480px）を **floating shadow + border-radius** で浮かせる
- 左サイド `position: fixed` の **aside** に店舗ラベル（業種 / 店舗名 / 補足）

### 共通CSS パターン
```css
.pc-aside { display: none; }  /* default mobile */

@media (min-width: 1024px) {
  body {
    background: linear-gradient(135deg, [color1] 0%, [color2] 100%);
    padding: 2rem 0;
  }
  .mobile-container, main {  /* 各テンプレのコンテナ */
    box-shadow: 0 30px 80px -20px rgba(0,0,0,0.18), 0 8px 16px -8px rgba(0,0,0,0.08);
    border-radius: 24px;
    margin-top: 2rem;
    margin-bottom: 2rem;
    min-height: auto;
  }
  .pc-aside {
    display: flex; position: fixed; top: 50%;
    flex-direction: column; gap: 1rem; z-index: 30;
    left: calc(50% - [half_of_container_width] - 64px);
    transform: translate(-100%, -50%);
    width: 180-220px; align-items: flex-start;
  }
  .pc-aside-title { /* SHOP PAGE 等のラベル */ }
  .pc-aside-shop { /* 店舗名 */ }
  .pc-aside-cat { /* 業種 */ }
  .pc-aside-note { /* 補足 */ }
}
```

| テンプレ | 背景画像（aidesigner生成） | グラデオーバーレイ | コンテナ幅 | aside テキスト色 |
|---|---|---|---|---|
| **T1 クリーン** | `pc-bg/T1_clean.webp`（ユーカリ+リネン+石） | 白〜淡緑半透明 | 430px | LINE緑タイトル / 濃灰本文 |

### PC背景画像の生成（aidesigner）

5テンプレすべての PC viewport 背景は **aidesigner** で生成し、`branding/dummy/pc-bg/` に WebP で配置。

```css
/* 共通パターン：背景画像 + テンプレ色グラデーションのオーバーレイ */
body {
  background:
    linear-gradient(135deg, rgba(...) 0%, rgba(...) 100%),   /* テンプレ色を被せる */
    url('../../branding/dummy/pc-bg/T1_clean.webp') center/cover no-repeat fixed;
}
```

ポイント：
- `center/cover no-repeat fixed`：スクロール時も固定、画面全面カバー
- グラデーションを **半透明（alpha 0.3〜0.7）** で被せ、テンプレ色を維持しつつ装飾も見せる
- 中央のモバイルコンテナはネガティブスペースに配置されるよう構図を意識（aidesigner プロンプトで "lots of negative space in the center" を指示）

### 🚀 公開ページへの反映（重要）

**PC背景はモック画面だけでなく、実際に公開される `secleva.com/SHOP-{id}` にもそのまま反映される設定**。

```
[Owner が選択したテンプレ ID]
    ↓
[公開ページ レンダリング]
    ├ モバイル: モバイルファースト UI（スマホサイズ）
    └ PC (≥1024px): モバイル UI を中央配置
                      + テンプレ別の PC背景画像（aidesigner生成・サーバー側で固定）
                      + テンプレ色グラデーションオーバーレイ
                      + 左 aside（店舗名・業種ラベル）
```

つまり：
- **オーナー側の操作不要**：テンプレ選択時に PC 背景も自動セット
- **店舗ごとに変えない**：同じテンプレを選んだ全店舗が同じ PC 背景を使う（5枚を全国の店舗で共有）
- **将来拡張**：店舗カテゴリやエリア別に PC 背景を差別化する余地は残す（その場合 `branding/dummy/pc-bg/T1_clean_kansai.webp` のような派生を作る）

- プレビュー画面 = 確認 ＋ 公開操作（最終ステップ）
- 「保存→確認→公開」が一直線になり、リテラシー低層も迷わない

### Preview のステータス別アクション

| 現在の状態 | バッジ | メインCTA | サブアクション | 公開ページへの導線 |
|---|---|---|---|---|
| **下書き** | 黄バッジ「下書き」（脈動） | お店ページを公開する | 一時的に非公開にする | 「公開ページを見る」リンク（テスト用） |
| **公開中** | 緑バッジ「公開中」 | 変更を反映する | 一時的に非公開にする | 「公開ページを見る」リンク |
| **一時休止中** | グレーバッジ「一時休止中」 | もう一度公開する | 下書きに戻す（任意） | 「公開ページを見る」（一時休止表示） |

### 重要な UX 判断（案A 採用）

| 観点 | 判断 |
|---|---|
| **公開後に公開ページに自動遷移するか？** | ❌ しない。Preview 画面に留まり、ユーザー任意で「公開ページを見る」リンクから新タブで見にいく |
| **理由** | リテラシー低層は「画面が勝手に変わる」体験で混乱しがち。自分の操作で開く方が安心 |
| **確認モーダルは必須？** | ✅ 必須。誤公開を防ぐワンクッション。文言で「いつでも非公開に戻せます」と書き、不可逆感を除く |
| **成功フィードバック** | 3層：ステータスバッジ変化＋トースト＋メインCTA 文言変化 → 公開された証拠を多重に提示 |
| **下書き状態でも「公開ページを見る」を出す理由** | テスト共有（友人レビュー等）のため。受け手側で「ページが見つかりません」になっても、運用上必要 |

## 🏷️ タグ（店舗特徴タグ）の操作仕様

Block 3「店舗特徴タグ」は **3エリア構成**：選択中タグ／候補タグ／オリジナルタグ追加。  
各エリアの ×（削除）と＋（追加）の挙動を以下に定義する。

### 3エリアの状態定義

| エリア | 視覚 | 役割 |
|---|---|---|
| **選択中タグ**（最上段） | LINE緑塗りピル＋× | 公開ページに表示される（最大10個） |
| **候補タグ**（中段） | 白枠ピル＋× | この店舗で「使う可能性のあるタグ」リスト |
| **オリジナルタグ追加**（最下段） | 入力欄＋追加ボタン | プリセット外の独自タグを新規作成 |

### 各操作の挙動

#### A. 選択中タグの ×（削除）→ 候補に戻す
```
[選択中]                      [選択中]
[× 女性専用][× 個室]   →    [× 個室]
                              ↓ ×タップでオブジェクトを候補に降格
[候補]                        [候補]
[深夜営業 ×][キッズOK ×]      [女性専用 ×][深夜営業 ×][キッズOK ×]
```
- **動作**：選択中エリアから削除 → 同じタグ名が **候補リストの先頭**に追加
- **カウンタ**：「5個選択中→4個選択中」に減少
- **ON/OFFトグル**：全体トグルが ON のまま（個別操作）
- **アニメーション推奨**：fadeOut 200ms → 候補先頭に slideIn 200ms

#### B. 候補タグの本体（テキスト）タップ → 選択中に追加
```
[候補]                        [候補]
[深夜営業 ×]タップ      →    （※「深夜営業」消える）
                              ↓
[選択中]                      [選択中]
[× 女性専用][× 個室]          [× 女性専用][× 個室][× 深夜営業]
```
- **動作**：候補リストから削除 → 選択中エリアの末尾に追加
- **カウンタ**：「5個選択中→6個選択中」に増加
- **制限**：選択中が **10個に達したらタップ無効化**＋トースト「最大10個まで」
- **アニメーション**：候補から fadeOut 200ms → 選択中末尾に slideIn 200ms

#### C. 候補タグの ×（削除）→ この店舗から永久削除
```
[候補]                        [候補]
[英語対応 ×]の×をタップ →    （※「英語対応」消える、選択中にも来ない）
```
- **動作**：候補リストから削除（**選択中には来ない**、シンプルに消える）
- **理由**：「この店舗では使わない」と決め打ち。視認ノイズを減らす
- **取り消し**：トーストに「元に戻す」ボタンを5秒表示
- **完全復帰**：「他のSNSを追加」のような「他の候補を見る」expanderで再表示可能（将来拡張）

#### D. オリジナルタグの追加 → 選択中に直接追加
```
[オリジナル入力欄]
[着替え貸出あり] [+ 追加]タップ
        ↓
[選択中]
[既存タグ群...][× 着替え貸出あり]  ← 末尾に追加、緑ピル
```
- **動作**：入力テキストを **選択中の末尾**に追加（候補をスキップ）
- **入力制限**：最大15文字、空白のみは無効、重複名は無効（トースト「同名のタグが既にあります」）
- **永続化**：このタグは「カスタムタグ」としてサーバー保存。**他店舗とは共有しない**（プライベート）
- **削除時の挙動**：選択中で × → 候補リストに戻る（プリセットと同じ扱い）
- **永久削除**：候補で × → この店舗から完全削除（再入力すれば復活）

### 連動するカウンタ表示

最下部の表示は常に動的更新：
```
🛈 [5個] 選択中・[最大10個] まで
```
- 色：選択中数 = 0 〜 9 → 緑、10達成 → 赤＋震えアニメーション
- 制限到達時は候補タップを無効化＋視覚フィードバック

### バックエンドのデータ構造（推奨）
```ts
type Shop = {
  tags: {
    selected: string[],   // 選択中（順番保持、最大10）
    candidates: string[], // 候補（プリセット + カスタム）
    customTags: string[], // この店舗で追加したカスタムタグ（候補とは別管理）
  }
}
```
- selected: 公開ページに表示される配列（順番もそのまま）
- candidates: 編集画面の「候補から選ぶ」エリアに出すリスト
- customTags: オリジナル追加分。候補から削除されても残る（再表示可能性のため）

### プリセットタグの全体マスター（実装時）

オーナーが × で削除しても、Sevleva 側で **再追加できる候補マスター**を持つ：

```
プリセット候補マスター（業種別）:
  共通: 女性専用, 個室, 駅近, 駐車場あり, 完全予約制, 当日予約OK, クレカ可, PayPay可
  マッサージ系: 深夜営業, シャワー完備, カウンセリングあり, 手ぶらOK
  整体系: 国家資格保有, プライベート空間, 女性スタッフ在籍
  アロマ系: オーガニック認証, ペット同伴可
  ナイト系: ボトルキープ可, カラオケ完備, 22時以降, VIP個室
  多言語: 英語対応, 中国語対応, 韓国語対応
```

→ 業種選択時に該当する候補を自動追加。オーナーは × で個別削除可能。

### エッジケース

| ケース | 挙動 |
|---|---|
| 選択中10個 + 候補タップ | タップ無効化＋トースト「最大10個まで」 |

## 📷 写真アップロード UX 設計

メインビジュアル・ロゴ・ギャラリー・メニュー写真すべて、共通のアップロードUXに統一する。

### 写真の3状態（共通）

| 状態 | バッジ表示 | サブラベル | バックエンド条件 |
|---|---|---|---|
| **custom** | バッジなし | 「マイ写真」 | `photo_url` あり（オーナーがアップロード） |
| **default** | `DEFAULT` 黒バッジ | 「デフォルト表示中」 | `photo_url` なし、業界デフォルトに match |
| **empty** | 破線枠＋📷アイコン | 「写真未設定」 | `photo_url` なし、デフォルトにも match しない |

### アップロードフロー（5ステップ）

#### ステップ1：選択（タップ → ネイティブピッカー）
オーナーが **「自分の写真をアップロード」** をタップ：
- iOS/Android のネイティブ写真ピッカーが起動
- 「写真ライブラリから選ぶ」 or 「カメラで撮る」 の選択肢
- 実装：`<input type="file" accept="image/*" capture="environment">`

#### ステップ2：プレビュー＋切り抜き（任意）
選択された写真をその場で表示：
- メインビジュアル：16:9 アスペクトに合わせて自動クロップ提案
- ロゴ：1:1 円形クロップ提案
- ギャラリー / メニュー：そのまま 1:1 表示
- オーナーは「このままでOK」または「位置を調整」を選択

#### ステップ3：アップロード進行
ローディング表示：
```
[ プログレスバー 70% ]
アップロード中... もう少しお待ちください
```
- 推奨：3秒以内に完了する圧縮（WebP変換・リサイズはバックエンド側で）
- ネットワーク切断時のリトライ機構
- 失敗時：明確な日本語エラー「写真を送れませんでした。電波が良い場所でもう一度試してください」

#### ステップ4：完了通知＋ステート切替
- DEFAULT バッジ → 消滅
- サブラベル：「デフォルト表示中」→「マイ写真」
- プレビュー画像が即更新
- トースト：**「写真を保存しました」** （3秒表示）
- 編集パネルは閉じない（連続編集可能に）

#### ステップ5：自動保存（無操作で確定）
- アップロード成功 = 自動でデータベース保存
- 「保存ボタン」を別途タップ不要（オプションで明示的保存も用意）
- 編集パネルを閉じても/別タブに行っても変更は保持

### 各箇所のUX分岐

#### メインビジュアル（Block 1、1枚）
```
[ 現状: DEFAULT表示 ]                  [ アップロード後 ]
┌──────────────────┐                  ┌──────────────────┐
│ ●デフォルト表示中 │                  │ [写真を選ぶ]      │
│ [プロが撮影した室内]│   →   →   →    │ [マイ写真の画像]   │
│ [写真を選ぶ]      │                  │                  │
└──────────────────┘                  └──────────────────┘
```
- 写真がない時：デフォルト00_hero.webp + 「デフォルト表示中」バッジ
- アップロード後：自分の写真 + 「変更」「削除」ボタン

#### ロゴ（Block 2、1枚、円形）
```
[ 未設定 ]                            [ アップロード後 ]
┌──────────────────┐                  ┌──────────────────┐
│ ⊙ 破線円         │                  │ ⊙ [マイロゴ画像]  │
│ 「ロゴ画像を選ぶ」│   →   →   →   →  │ 「変更」「削除」   │
└──────────────────┘                  └──────────────────┘
```
- デフォルトなし（オーナー必須）
- 円形にクロップ
- 推奨サイズ：512×512px 以上

#### ギャラリー（Block 4、最大6枚）
```
[ 6枚全部DEFAULT ]                    [ 部分アップロード ]
┌──────────────────────┐              ┌──────────────────────┐
│ DEFAULT×6           │              │ マイ×3, DEFAULT×3   │
│ [自分の写真を       │   →   →   →   │ [もう3枚追加できる] │
│  アップロード(最大6)]│              │ [長押しで並び替え]   │
└──────────────────────┘              └──────────────────────┘
```
- 「自分の写真をアップロード(最大6枚)」CTAで複数選択可
- アップロード後はオーナー写真でデフォルトを上書き
- 6枚未満の場合、残りはデフォルトで埋める
- 長押しでドラッグ並び替え

#### メニュー写真（Block 5、メニュー件数 × 1枚）
```
[ メニュー行クリック → アコーディオン展開 ]
┌──────────────────────────────────────┐
│ 60分もみほぐし    [編集]             │
│ ┌─ パネル展開 ───────────────────┐ │
│ │ [DEFAULT画像 / マイ写真]       │ │
│ │ [自分の写真をアップロード]      │ │
│ │ デフォルトから選ぶ 4サムネ      │ │
│ │ [削除] [保存]                   │ │
│ └────────────────────────────────┘ │
└──────────────────────────────────────┘
```
- 各メニューにつき1枚
- アップロード or デフォルト4枚から選択
- 削除でデフォルトに戻す

### ポストアップロード管理機能

#### 写真の入れ替え
- アップロード済みの写真の上にタップ → 「変更」or「削除」ダイアログ
- 「変更」：再度ピッカー起動
- 「削除」：デフォルトに戻る（確認ダイアログ）

#### 並び替え（ギャラリーのみ）
- 長押し → ドラッグで並び替え
- 視覚的フィードバック（持ち上がる影、ドロップ位置のハイライト）
- 並び順は即保存

#### 一括操作
- 「全部デフォルトに戻す」ボタン（オーナー写真→全削除）
- 確認ダイアログ「すべての写真を削除します。よろしいですか？」

### 推奨ファイル仕様（バックエンド処理）

| 項目 | 仕様 |
|---|---|
| 受け入れ形式 | JPEG / PNG / WebP / HEIC（iOSデフォルト） |
| 最大ファイルサイズ | 10MB／枚（クライアント側でリジェクト） |
| 自動変換 | WebP に統一、3 サイズ生成（thumb 200/medium 800/full 1600） |
| 自動最適化 | EXIF 削除、ロスレス圧縮 |
| アスペクト | メインビジュアル 16:9, ロゴ 1:1, ギャラリー 1:1, メニュー 1:1 |
| ストレージ | S3 互換（CloudFront / Cloudflare R2 等） |

### エラーハンドリング（日本語UX）

| エラー | 表示メッセージ |
|---|---|
| ファイルサイズ超過 | 「写真が大きすぎます。10MB以下にしてください」 |
| 形式不正 | 「JPG・PNG・HEICのみ使えます」 |
| ネットワーク失敗 | 「写真を送れませんでした。電波が良い場所でもう一度試してください」 |
| サーバーエラー | 「うまく送れませんでした。しばらくしてからもう一度お試しください」 |

### 自動保存 vs 明示的保存

**現状の設計**：アップロード成功 = 自動保存（オーナーは「保存ボタン」を意識しない）

**理由**：
- リテラシー低層は「保存ボタンを押し忘れる」リスクが高い
- 「変更が即反映される」感覚が安心につながる
- 編集パネル下部に「保存」ボタンは置くが、自動保存済みなのでもう一度押しても変化なし

| ログイン / サインイン | ログイン（最低限）／自動ログイン | サインインは使わない |
| アップロード | **写真を選ぶ／写真を送る** | アクションを直球で |
| プレビュー | プレビュー（既出語） + 補足「お客さんに見える画面」 | 1度説明する |
| 編集 | **編集** ＋ ✏ アイコン併用 | 文字 + 視覚の二重表現 |
| 削除 | **削除** ＋ 🗑 ＋ 確認ダイアログ | 不可逆動作は安全側 |
| キャンセル | **キャンセル** | 既出語 |
| 公開 | **お店ページを公開する**（フル文） | 何をどうするかを明示 |
| 保存 | **とりあえず保存** ／ 保存する | 続きから戻れる安心感を付与 |
| OK / Submit | **決定** ／ **次へ進む** | 完了感を出す |

### 文言フォーマットの原則
1. **動詞 + 目的語**（暗黙でなく明示）：「保存」→「お店ページを保存する」
2. **「とりあえず」「いつでも変えられます」**で**後戻り可能性**を強調 → 触る心理障壁を下げる
3. **サブテキスト**で**用途**をワンライン補足：「リンクをコピー」→「メモに貼り付けできます」
4. **ヘルパーバナー**で**そのページ全体でできること**を1〜2文：「公開前でも、リンクを送って下見してもらえます」
5. **絵文字は控えめ**：1要素に最大1つ。Phosphor アイコンで代用

### コピーNG例 → OK例

### Helper Banner（補助案内）の使い所
こんな時に**ステータス行直下の薄緑バナー**を追加：
- ユーザーの行動意図が画面の文面だけでは伝わらない時
- 下書き／公開／同期中 などの状態によって動作が変わる時
- 「触ってもいいんだ」と背中を押したい時

例：
> 💡 公開前でも、リンクを友だち・スタッフに送って下見してもらえます。

### 「リンクを送る」「リンクをコピー」の文言設計判断（実装メモ）

| 項目 | 設計判断 | 理由 |
|---|---|---|
| 呼称 | "URL" → **"リンク"** | 日本の50代以上での認知率が圧倒的に高い |
| 「共有」 | → **"送る"** | 「共有」は SNS 寄りの用語、「送る」が日常語 |
| 「コピー」 | そのまま採用 ＋ サブテキスト「メモに貼り付け」 | コピー自体は浸透。用途を補足することで使い道を提示 |
| アイコン | 共有=ph-share-network / コピー=ph-copy | 標準的な見た目を維持 |
| バナー | LINE緑10%背景＋ Info アイコン | プレビュー画面のみの限定表示でノイズ最小化 |

実装時にもこの判断ロジックを踏襲し、新規ボタン追加時は「**動詞**は日常語？」「**目的語**は明示されているか？」「**後戻り可能**と分かるか？」を3点チェックする。
